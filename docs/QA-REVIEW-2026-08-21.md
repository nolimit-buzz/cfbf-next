# Frontend QA Review — 21 August 2026

**Scope:** `frontend/` — Next.js 16.2.6, React 19.2.4, App Router, Strapi-backed
(`https://cms.climatefacility.org`) with bundled defaults per page.

**Method:** static review of every route, component, CMS defaults module and API route.
Link graph, anchor targets, form contracts (client ↔ server), asset references, error and
not-found paths, SEO metadata, and accessibility affordances.

**Result:** 18 findings — 6 P1, 6 P2, 6 P3. No blocking defect in the contact form or the
CMS fallback layer; the significant issues are in routing/404 handling and in the gap
between what the CMS controls and what the project detail pages actually render.

## P1 — Fix before handover

### 1. `/projects/<anything>` renders Project 01 instead of 404

**File:** `components/projects/ProjectDetailClient.tsx:177`

```ts
const projectId = resolvedParams.id || '01';
const project = projects[projectId] || projects["01"];
```

Any unknown slug — `/projects/99`, `/projects/foo`, a stale shared URL — silently serves
the First Electric case study with an HTTP 200.

Knock-on effects:

- Unlimited duplicate-content URLs for the same page. Search engines will index them.
- `projectIds.indexOf(projectId)` returns `-1`, so the prev/next pager computes
  `prevId = "05"`, `nextId = "01"` (`ProjectDetailClient.tsx:180-183`) — wrong, though
  currently masked by the fallback.

**Fix:** resolve the project in the server component (`app/projects/[id]/page.tsx`) and
call `notFound()` on a miss, passing the resolved project down as a prop. This also lets
you add a real `generateMetadata` (see #9 note).

---

### 2. Unknown news article returns HTTP 200 (soft 404)

**File:** `app/news/[id]/page.tsx:40-48`

The lookup is correct — `article` is `null` on a miss, and `NewsDetailClient` renders a
proper branded "Article Not Found" screen with a back-to-hub CTA. But the HTTP status is
still **200**, so crawlers index the miss page as real content.

**Fix:** call `notFound()` in `NewsDetail` when `article` is null, rather than passing
`null` into the client component. Keep the existing not-found copy by moving it into
`app/news/[id]/not-found.tsx` so the CMS-authored labels survive.

---

### 3. No `app/not-found.tsx`

Once #1 and #2 return real 404s, every one of them lands on Next's unstyled default page
— no navbar, no footer, no brand, no way back.

**Fix:** add `app/not-found.tsx` reusing `GlassHero` / `InnerPageHero` so a 404 looks like
part of the site.

---

### 4. Project detail pages are hardcoded, not CMS-driven

The projects **index** reads Strapi (`lib/cms/projects-defaults.ts`, entries keyed
`projectId: '01'` … `'06'`), and its cards link to `/projects/${p.projectId}`.

The projects **detail** page reads the static `lib/projectsData.ts`. So do two hardcoded
lookup tables inside it:

- `getProjectSDGs()` — `switch` on `'01'`…`'06'`, `default: [7]`
  (`ProjectDetailClient.tsx:43`)
- `PROJECT_STATES` — `Record<string, string[]>` keyed `'01'`…`'06'`
  (`ProjectDetailClient.tsx:55`)
- `getExpectedImpactText()` — branches on `p.id === '02'` / `'04'`
  (`ProjectDetailClient.tsx:160`)

**Consequence:** an editor who adds project `07` in Strapi gets a working card on
`/projects` whose link renders **Project 01** (via finding #1), with fallback SDGs and an
empty map. Editing existing project copy in the CMS changes the index card but *not* the
detail page — the two can drift out of sync silently.

This is the largest gap between what the CMS appears to control and what the site
actually renders. Two acceptable resolutions, but one must be chosen deliberately:

- **(a)** Wire the detail page to the CMS — move the per-project SDG list, state list and
  narrative fields into the Strapi project component.
- **(b)** Document explicitly that projects are a code-deploy-only content type, and
  remove or lock the project fields in Strapi so no editor believes otherwise.

### 5. Placeholder phone number is live on `/contact`

**File:** `lib/cms/contact-defaults.ts:100-109`

```ts
officeAddressLineOne: 'InfraCredit House,',
officeAddressLineTwo: 'Lagos, Nigeria.',
emailAddress:  'info@infracredit.ng',
phoneNumber:   '+234 (1) 234 5678',   // ← placeholder
phoneHref:     'tel:+23412345678',    // ← placeholder
```

A dummy number rendered as a tappable `tel:` link on the live contact page. The office
address is also incomplete (no street). Needs the real details supplied — either in
Strapi or in the defaults, but the defaults should not ship a fake number regardless,
since they are what renders during any CMS outage.

---

### 6. CMS payloads are `console.log`ged in production

Seven client components dump their entire section tree to the browser console on render:

```
components/about/AboutSections.tsx:95
components/contact/ContactSections.tsx:190
components/eligibility/AssessmentClient.tsx:106
components/eligibility/EligibilitySections.tsx:239
components/home/HomeSections.tsx:75
components/how-it-works/HowItWorksSections.tsx:146
components/impact/ImpactSections.tsx:245
components/projects/ProjectsSections.tsx:196
```

Noisy and unprofessional the moment anyone opens devtools, and it exposes the full CMS
response shape.

**Fix:** gate behind `process.env.NODE_ENV !== 'production'`, or delete. The server-side
`reportFallback` logging in `lib/cms/fetchPage.ts` is deliberate and should stay.

## P2 — Should fix

### 7. Every image is a raw `<img>` — 70 of them, none optimised

`next/image` is not imported anywhere in the codebase.

| Metric | Count |
| --- | --- |
| `<img>` elements | 70 |
| with `loading="lazy"` | 28 |
| with explicit `width`/`height` | 2 |

Consequences: no responsive `srcset`, no AVIF/WebP conversion, no automatic lazy loading
below the fold, and layout shift on almost every image. This is the single largest Core
Web Vitals item on the site.

**Fix:** migrate to `next/image`, adding the remote hosts to `images.remotePatterns` in
`next.config.ts` (which currently configures neither).

---

### 8. 131 hotlinked Unsplash stock images

`images.unsplash.com` appears **131 times** across `lib/cms/*-defaults.ts`. By contrast,
`res.cloudinary.com` — the project's own asset host — appears 15 times.

Two problems: production imagery depends on a third-party CDN with no uptime or
rate-limit guarantee to this project, and the photos are generic stock rather than
portfolio assets.

**Fix:** migrate to the Cloudinary pattern already established in
`lib/cms/impact-defaults.ts:45-60`, or get explicit client sign-off that stock imagery is
the intended final state.

---

### 9. OG share image is a stock Unsplash photo

**File:** `app/layout.tsx:33`

```ts
url: "https://images.unsplash.com/photo-1509391366360-2e959784a276?q=80&w=1200",
```

Every share of the site on LinkedIn, X, WhatsApp or Slack unfurls with a random Unsplash
landscape. Needs a branded 1200×630 asset in `public/`.

Related: `/projects/[id]` has no `generateMetadata` at all — it relies on React 19
hoisting `<title>`/`<meta>` from a client component. That works for browsers but is
unreliable for social crawlers. Folding this into the fix for #1 solves both.

---

### 10. No `sitemap.xml` and no `robots.txt`

Neither `app/sitemap.ts` nor `app/robots.ts` exists. For a content site with dynamic
`/news/[id]` and `/projects/[id]` routes, this materially hurts discovery — those pages
are linked only from index pages and the navbar mega-menu.

**Fix:** both are roughly 20 lines in Next 16; the sitemap can enumerate news articles
from `getNewsArticles()` and projects from the same source chosen in #4.

---

### 11. Keyboard focus is invisible sitewide

| Pattern | Count |
| --- | --- |
| `focus:outline-none` | 136 |
| `focus-visible:` | **0** |

The native focus ring is suppressed everywhere and nothing replaces it. Keyboard and
screen-reader users cannot tell where they are — on the contact form, the eligibility
assessment, every nav link, every CTA. This is a **WCAG 2.1 SC 2.4.7 (Focus Visible)
failure**, which matters for a facility funded by FCDO/BII.

**Fix:** pair every suppression with a visible replacement —
`focus-visible:ring-2 focus-visible:ring-brand-primary focus-visible:ring-offset-2`. A
single global rule in `app/globals.css` covers most cases; the interactive SVG map paths
in `ProjectDetailClient.tsx` already do this correctly and can serve as the model.

---

### 12. Video modal autoplay is blocked by the browser

**File:** `components/impact/ImpactSections.tsx:887-891`

```tsx
<video src={selectedVideo.url} autoPlay controls className="..." />
```

`autoPlay` without `muted` is blocked by Chrome and Safari, so opening a story video
shows a paused first frame. Recoverable (controls are present) but reads as broken.

**Fix:** add `muted` and `playsInline`, or drop `autoPlay` and let the poster frame stand.
The hero video (`components/home/Hero.tsx:160`) gets this right.

## P3 — Polish

### 13. `alert()` used for "copy link"

`components/news/NewsDetailClient.tsx:74-79` — a native browser alert, which does not
match the design language. `navigator.clipboard.writeText` is also unguarded: it rejects
on non-secure origins and in some embedded browsers, and the alert claims success either
way. Use an inline toast and `await` the promise.

### 14. Dead query params in the assessment → contact handoff

`components/eligibility/AssessmentClient.tsx:262-273` sends five params:

```
readiness, score, tech, capacity, customers
```

`ContactSections.tsx` reads only `readiness`, `score` and `tech`. The contact form's
**required** Capacity field is left blank even though the assessment already collected
the answer — a small but avoidable re-entry.

### 15. `?readiness=` is not validated

`ContactSections.tsx` treats any value other than `qualified` as technical-assistance —
so a hand-typed `/contact?readiness=excluded` renders an encouraging blue banner. Not
reachable through the UI (finding: the excluded outcome correctly routes back to
`/eligibility` instead), but worth whitelisting the two valid values.

### 16. Social icons are all inert

`lib/cms/global-defaults.ts:22-27` ships all five social URLs empty. This is deliberate
and degrades gracefully — the footer renders non-clickable marks with a "link coming
soon" title rather than dead `href="#"` links. **Flagged as outstanding content, not a
bug:** the real handles still need to be supplied in Strapi.

### 17. Cookie consent is decorative

`components/CookieBanner.tsx` stores accept/decline in `localStorage`, but nothing is
gated on the result. Harmless today (no analytics or marketing tags are loaded), but:

- it must actually gate loading before any tag is added, and
- check the `/privacy` copy does not already claim cookie controls that do not exist.

### 18. CMS base URL is hardcoded

`lib/cms/config.ts:18` hardcodes `https://cms.climatefacility.org` with no environment
override, and `netlify.toml` documents this as intentional. Flagged for the client's
awareness only: **moving or renaming the CMS requires a code change and a redeploy**, not
a dashboard setting.

## Suggested fix order

1. **P1 #1, #2, #3 together** — one focused routing change across
   `app/projects/[id]/page.tsx`, `app/news/[id]/page.tsx`, and a new `app/not-found.tsx`.
   Fold in the `generateMetadata` from #9 while touching the project route.
2. **P1 #6 and #5** — strip the console logs, supply the real phone and address. Trivial,
   high visibility.
3. **P1 #4** — needs a scope decision from the client before any code is written.
4. **P2 #10 and #9** (SEO), then **#11** (accessibility), then **#7 / #8** (images —
   largest effort, best measured with Lighthouse before and after).
5. **P3** as time allows.

## Verification checklist

**Build**

- `npm run build` — no new type errors; confirm the `notFound()` routes prerender.
- `npm run lint`.

**Routing / 404**

- `/projects/zzz` and `/news/zzz` → branded 404 page, **404 status in the network tab**.
- `/projects/01` … `/projects/06` all render, with correct prev/next wrap at both ends.
- `/news/1` renders; the prev/next pager is absent at the ends of the list.

**Contact form** (needs `BREVO_API_KEY`, `BREVO_FROM_EMAIL`, `CONTACT_TO_EMAIL`)

- Submit as each of developer / investor / donor; confirm both the internal enquiry and
  the acknowledgement arrive, and that Reply-To on the internal mail is the enquirer.
- POST a deliberately invalid payload (`curl` with a missing field) and confirm the
  server's error string surfaces inline in the form.

**Eligibility assessment**

- Drive each of the three outcomes (excluded / technical-assistance / qualified).
- Confirm excluded does **not** offer the contact route.
- Confirm qualified prefills the contact message body and technology select.

**Accessibility**

- Tab through `/contact`, the navbar and the mega-menu — focus must be visible at every
  stop.
- Check the interactive Nigeria map is reachable and operable by keyboard on a project
  page.

**Performance**

- Lighthouse on `/` and `/projects`, before and after the image work.
